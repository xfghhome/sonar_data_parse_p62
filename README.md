# P62 文件解析器

全向声呐数据文件（.P62）的解析与可视化工具。

## 主要特性

- ✅ **多圈扫描处理**：自动检测并分离多圈扫描数据，避免角度重复和图像畸变
- ✅ **统一角度约定**：极坐标图和笛卡尔图使用一致的角度约定，确保图像对齐
- ✅ **智能网格构造**：使用 mid-point 方式构造角度边界，处理非均匀角度采样
- ✅ **端序分析**：同时解析 param3 的小端和大端，帮助确定正确的数据格式
- ✅ **有效范围过滤**：支持只使用 param1 指示的有效距离范围，排除盲区数据
- ✅ **零位偏置校正**：自动将每圈的第一个方位索引作为 0° 基准
- ✅ **向量化处理**：使用 NumPy 向量化操作，提升性能

## 文件格式说明

根据文件结构分析，.P62 文件包含：

- **文件结构**：固定长度记录（每条 695 字节）
- **记录数**：1506 条
- **每条记录包含**：
  - **头部（21 字节）**：
    - 0x00-0x03: Magic 标识 `FE 14 10 01`
    - 0x04-0x07: Unix 时间戳（uint32 小端）
    - 0x08-0x09: 方位索引（uint16 小端，范围 0-1567）
    - 0x0A-0x0B: 参数1（1313，有效距离 bin 数）
    - 0x0C-0x0D: 参数2（1348，总采样点数，包含盲区）
    - 0x0E-0x0F: 量程设置（50，表示 5.0 米，单位 0.1m）
    - 0x10-0x11: 编码器分辨率（1568，对应 360°）
    - 0x12-0x13: 参数3（同时解析小端和大端，用于格式验证）
    - 0x14: 状态字节
  - **回波数据（674 字节）**：
    - 从 0x15 开始
    - 包含 1348 个 4-bit 强度样本（每个字节包含 2 个样本）
    - 强度范围：0-15

## 使用方法

### 1. 基本解析（不生成图像）

```bash
python parse_p62.py 222.P62
```

输出文件统计信息，包括扫描圈数、param3 端序分析等。

### 2. 完整解析与可视化

```bash
# 生成所有可视化（默认使用单圈数据）
python parse_p62.py 222.P62 --all

# 或选择特定视图
python parse_p62.py 222.P62 --polar      # 极坐标视图
python parse_p62.py 222.P62 --cartesian  # 笛卡尔坐标视图
python parse_p62.py 222.P62 --scan       # 扫描模式图

# 高级选项
python parse_p62.py 222.P62 --all --cycle-idx 0        # 使用第一圈数据（默认）
python parse_p62.py 222.P62 --all --cycle-idx 1        # 使用第二圈数据
python parse_p62.py 222.P62 --all --all-cycles          # 使用所有圈的数据（不推荐，可能产生畸变）
python parse_p62.py 222.P62 --all --valid-range-only    # 只使用有效距离范围（排除盲区）

# 导出数据为 NumPy 格式（便于后续分析）
python parse_p62.py 222.P62 --export sonar_data.npz
```

### 3. 命令行参数说明

| 参数 | 说明 |
|------|------|
| `--all` | 生成所有可视化（极坐标、笛卡尔、扫描模式） |
| `--polar` | 只生成极坐标视图 |
| `--cartesian` | 只生成笛卡尔坐标视图 |
| `--scan` | 只生成扫描模式图 |
| `--export <file>` | 导出数据为 NPZ 格式 |
| `--single-cycle` | 只使用单圈扫描数据（默认开启） |
| `--all-cycles` | 使用所有圈的数据（可能产生角度重复） |
| `--cycle-idx <N>` | 选择要使用的圈索引（默认 0，第一圈） |
| `--valid-range-only` | 只使用 param1 指示的有效距离范围 |

## 输出文件

### 可视化图像
- `polar_view.png` - 极坐标视图（俯视，0°在顶部（北），顺时针方向）
- `cartesian_view.png` - 笛卡尔坐标视图（平面投影，与极坐标图角度约定一致）
- `scan_pattern.png` - 扫描模式（方位索引随时间变化，用于检测圈数）

### 数据导出
使用 `--export` 选项可以导出解析后的数据为 NumPy 压缩格式（.npz），包含：
- `timestamps` - 时间戳数组
- `azimuth_indices` - 方位索引数组
- `angles_deg` - 角度数组（度）
- `angles_rad` - 角度数组（弧度）
- `intensity` - 强度矩阵（方位数 × 距离采样点数）
- `range_max` - 最大量程（米）
- `num_samples` - 距离采样点数
- `encoder_res` - 编码器分辨率

加载示例：
```python
import numpy as np
data = np.load('sonar_data.npz')
intensity = data['intensity']
angles = data['angles_rad']
```

## 数据说明

- **时间戳**：Unix 时间戳（秒级）
- **方位角**：`角度 = (方位索引 / 1568) × 360°`
  - 默认应用零位偏置：每圈的第一个方位索引作为 0° 基准
  - 角度范围：0-360°
- **距离分辨率**：
  - 总采样点数：`dr_total = 5.0 m / 1348 ≈ 3.71 mm`
  - 有效采样点数：`dr_valid = 5.0 m / 1313 ≈ 3.81 mm`
  - param1 和 param2 的差异（35 个 bin）通常对应近距离盲区或换能器振铃空白
- **回波强度**：4-bit 值（0-15），表示每个距离单元的回波强度
- **扫描圈数**：自动检测，通过方位索引回落判断新圈开始

## 重要修复与改进

### 已修复的问题

1. **多圈扫描混叠问题** ✅
   - 问题：多圈扫描数据混在一起，导致重复角度和图像畸变
   - 解决：自动检测圈数，默认只使用单圈数据，对相同方位索引聚合

2. **极坐标网格构造问题** ✅
   - 问题：假设角度均匀分布，但实际存在跳变和缺失
   - 解决：使用 mid-point 方式构造角度边界，处理非均匀角度采样

3. **角度约定不一致** ✅
   - 问题：极坐标图和笛卡尔图使用不同的角度约定，图像不对齐
   - 解决：统一角度转换函数，确保两张图使用相同的角度约定

4. **param3 端序问题** ✅
   - 问题：param3 的端序不确定，可能影响数据解析
   - 解决：同时解析小端和大端，在统计信息中显示两种端序的分析结果

5. **距离轴 bin 处理** ✅
   - 问题：距离轴使用不当，可能导致图像偏移
   - 解决：正确使用 bin center 和 bin edge 构造网格

6. **param1/param2 差异** ✅
   - 问题：param1（1313）和 param2（1348）的差异被忽略
   - 解决：提供 `--valid-range-only` 选项，只使用有效距离范围

7. **azimuth_idx 零位偏置** ✅
   - 问题：每圈起始方位索引可能不同，导致角度偏移
   - 解决：自动将每圈的第一个方位索引作为 0° 基准

8. **性能优化** ✅
   - 问题：笛卡尔图绘制使用 Python 循环，性能较差
   - 解决：使用 `np.maximum.at()` 向量化操作

## 注意事项

1. **角度方向**：
   - 极坐标图：0° 在顶部（北），顺时针方向为正
   - 笛卡尔图：与极坐标图使用相同的角度约定，确保图像对齐
   - 如需调整，修改 `convert_angle_for_plotting()` 函数

2. **多圈数据处理**：
   - 默认只使用第一圈数据（`--single-cycle`），避免角度重复
   - 使用 `--all-cycles` 会显示所有圈，但可能导致图像畸变
   - 使用 `--cycle-idx` 可以选择特定圈的数据

3. **有效范围过滤**：
   - param1（1313）和 param2（1348）的差异（35 个 bin）通常对应近距离盲区
   - 使用 `--valid-range-only` 可以排除这些无效数据，但可能丢失部分信息

4. **时间戳**：文件中的时间戳为 Unix 时间戳。示例文件显示为 2025-04-02，这可能是设备时钟设置问题或时间戳格式需要进一步验证。

5. **4-bit 解包顺序**：当前实现假设低 4 位在前，高 4 位在后。如果实际数据顺序相反，需要调整解包逻辑。

6. **距离映射**：假设量程设置字段的单位是 0.1 米（50 → 5.0 米）。如果实际单位不同，需要调整 `range_max` 的计算。

7. **param3 端序**：统计信息中会显示 param3 的两种端序解析结果。通常大端值（253）比小端值（64768）更合理，但需要根据实际设备文档确认。
